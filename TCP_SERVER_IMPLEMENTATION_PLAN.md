# Практический план написания TCP-сервера мессенджера на C#/.NET

## 1. Цель разработки

| Параметр | Решение для MVP |
|---|---|
| Основа | Существующий проект `server/TCP_Chat_` |
| Язык | C# |
| Платформа | .NET 10 |
| Транспорт | TCP через `TcpListener` и `TcpClient` |
| Формат данных | JSON Lines: один JSON-объект на строку |
| База данных | SQL Server из текущей схемы `DB_query/CompileDB.sql` |
| Доступ к БД | ADO.NET через `Microsoft.Data.SqlClient` |
| Чаты | Личные и простые групповые чаты |
| Сообщения | Только текстовые |
| Клиенты | Текущие `Client1` и `Client2` |

## 2. Что не переписываем

| Уже есть | Как используем |
|---|---|
| `TcpListener` | Оставляем для приёма подключений |
| `TcpClient` | Оставляем для соединения с клиентом |
| Асинхронные методы | Сохраняем `async/await` |
| Порт `8888` | Оставляем на этапе разработки |
| `Client1` и `Client2` | Переводим с обычного текста на JSON |
| `TCP_Chat_.sln` | Продолжаем разработку в текущем решении |

## 3. Целевая структура кода

| Файл | Класс | Ответственность |
|---|---|---|
| `Program.cs` | Точка входа | Создание зависимостей и запуск сервера |
| `TcpServer.cs` | `TcpServer` | Запуск listener и приём клиентов |
| `ClientConnection.cs` | `ClientConnection` | Работа с одним TCP-соединением |
| `ConnectionManager.cs` | `ConnectionManager` | Поиск активного пользователя и отправка ему событий |
| `MessageRouter.cs` | `MessageRouter` | Разбор команды `type` и вызов обработчика |
| `AuthService.cs` | `AuthService` | Регистрация, вход и выход |
| `ChatService.cs` | `ChatService` | Создание чатов, управление участниками и проверка доступа |
| `MessageService.cs` | `MessageService` | Сохранение, история и доставка сообщений |
| `UserRepository.cs` | `UserRepository` | SQL-запросы к таблице `users` |
| `ChatRepository.cs` | `ChatRepository` | SQL-запросы к `chats` и `chat_members` |
| `MessageRepository.cs` | `MessageRepository` | SQL-запросы к `messages` |
| `Models/*.cs` | Модели | Данные пользователя, чата и сообщения |
| `Protocol/*.cs` | DTO-команды | Запросы и ответы TCP-протокола |

Рекомендуемые папки внутри `server/TCP_Chat_/TCP_Chat_`:

```text
TCP_Chat_/
├── Program.cs
├── TcpServer.cs
├── ClientConnection.cs
├── ConnectionManager.cs
├── MessageRouter.cs
├── Services/
├── Data/
├── Models/
└── Protocol/
```

## 6. Этап 2 — подключить БД из C#

Создать `Database.cs` с фабрикой подключений.

| Метод | Назначение |
|---|---|
| `CreateConnection()` | Создать `SqlConnection` |
| `OpenConnectionAsync()` | Открыть подключение |
| `ExecuteAsync()` | Выполнить INSERT/UPDATE/DELETE |
| `QueryAsync()` | Получить данные |

Строку подключения хранить не в коде, а в переменной окружения или конфигурации:

```text
Server=localhost;Database=Messenger;Trusted_Connection=True;TrustServerCertificate=True;
```

Правила работы с БД:

| Правило | Требование |
|---|---|
| Подключения | Открывать только на время запроса |
| SQL | Использовать параметризованные запросы |
| Ресурсы | Использовать `await using` |
| Ошибки | Логировать на сервере, клиенту отдавать безопасное сообщение |
| Транзакции | Использовать при создании чата и его участников |

## 7. Этап 3 — переработать сетевую основу

### `TcpServer`

| Шаг | Реализация |
|---:|---|
| 3.1 | Создать `TcpListener(IPAddress.Any, 8888)` |
| 3.2 | Запустить `Start()` |
| 3.3 | В цикле вызывать `AcceptTcpClientAsync()` |
| 3.4 | Для каждого клиента создавать `ClientConnection` |
| 3.5 | Запускать `ProcessAsync()` без блокировки приёма новых клиентов |
| 3.6 | Передавать `CancellationToken` для остановки |
| 3.7 | При завершении вызывать `Stop()` и закрывать соединения |

### `ClientConnection`

| Поле/метод | Назначение |
|---|---|
| `TcpClient Client` | TCP-соединение |
| `long? UserId` | Пользователь после login |
| `StreamReader Reader` | Чтение строк JSON |
| `StreamWriter Writer` | Отправка JSON |
| `ProcessAsync()` | Основной цикл чтения команд |
| `SendAsync()` | Потокобезопасная отправка ответа |
| `Close()` | Корректное закрытие соединения |

Обязательное поведение:

| Событие | Действие |
|---|---|
| `ReadLineAsync()` вернул `null` | Завершить соединение |
| Пришёл пустой запрос | Вернуть ошибку валидации |
| Пришёл плохой JSON | Вернуть `invalid_json`, не завершать сервер |
| Пользователь не вошёл | Разрешить только `register`, `login`, `ping` |
| Клиент отключился | Удалить его из `ConnectionManager` |

## 8. Этап 4 — управление подключениями

Создать `ConnectionManager` на основе:

```text
ConcurrentDictionary<long, ClientConnection>
```

| Метод | Назначение |
|---|---|
| `Add(userId, connection)` | Добавить активного пользователя |
| `Remove(userId)` | Удалить пользователя при отключении |
| `TryGet(userId, out connection)` | Найти подключение |
| `SendToUserAsync(userId, event)` | Отправить событие одному пользователю |
| `SendToChatMembersAsync(chatId, event)` | Отправить событие участникам чата |

Если пользователь входит с двух устройств, для простого MVP разрешить одно активное соединение и закрывать старое.

## 9. Этап 5 — реализовать JSON-протокол

### Общие поля запроса

| Поле | Тип | Обязательно | Назначение |
|---|---|---:|---|
| `type` | `string` | Да | Название команды |
| `requestId` | `string` | Да | Связь запроса и ответа |
| `token` | `string` | Для защищённых команд | Идентификатор сессии |

### Команды сервера

| Команда | Поля | Результат |
|---|---|---|
| `register` | имя, фамилия, email/телефон, пароль | Создан пользователь |
| `login` | email/телефон, пароль | `userId` и `token` |
| `logout` | token | Сессия закрыта |
| `find_user` | email/телефон | Данные пользователя |
| `create_direct_chat` | `userId` второго участника | `chatId` |
| `create_group_chat` | название, список `userId` | `chatId` |
| `add_chat_member` | `chatId`, `userId` | участник добавлен |
| `remove_chat_member` | `chatId`, `userId` | участник удалён |
| `get_chats` | token | Список чатов |
| `get_messages` | `chatId`, `limit`, `beforeId` | История сообщений |
| `send_message` | `chatId`, `content` | Сохранённое сообщение |
| `ping` | нет | `pong` |

### Формат ответа

| Тип ответа | Поля | Назначение |
|---|---|---|
| Успех | `type`, `requestId`, данные | Результат команды |
| Ошибка | `type=error`, `requestId`, `code`, `message` | Ошибка обработки |
| Событие | `type=message`, данные сообщения | Входящее сообщение без запроса |

## 11. Этап 7 — личные и групповые чаты

| Шаг | Действие |
|---:|---|
| 7.1 | Для direct-чата найти второго пользователя |
| 7.2 | Для group-чата проверить название и список участников |
| 7.3 | Проверить, что пользователь не создаёт direct-чат с самим собой |
| 7.4 | Найти существующий direct-чат или создать новый чат |
| 7.5 | В транзакции добавить создателя и участников в `chat_members` |
| 7.6 | Вернуть клиенту `chatId` и тип чата |
| 7.7 | Для group-чата разрешить создателю добавить участника |
| 7.8 | Для MVP разрешить создателю удалить участника |

Каждая команда `get_messages` и `send_message` обязана проверять наличие пользователя в `chat_members`. Для MVP создатель группы считается её администратором; отдельную таблицу ролей пока не добавлять.

### Правила группового чата

| Правило | Решение MVP |
|---|---|
| Название группы | Обязательно, до 100 символов |
| Количество участников | Например, от 2 до 50 |
| Создатель | Первый участник и администратор |
| Добавление участников | Только создатель |
| Удаление участников | Только создатель |
| Отправка сообщений | Любой участник |
| История | Общая для всех участников |
| Роли и права | Отложить до следующей версии |

## 14. Минимальные тесты

| Тест | Ожидаемый результат |
|---|---|
| `ping` до входа | Сервер отвечает `pong` |
| Неверный JSON | Сервер отвечает ошибкой и продолжает работу |
| Регистрация нового пользователя | Пользователь появляется в `users` |
| Повторная регистрация того же телефона | Возвращается ошибка дубликата |
| Неверный пароль | Вход запрещён |
| Отправка без login | Возвращается `unauthorized` |
| Отправка в чужой чат | Возвращается `forbidden` |
| Отправка сообщения онлайн | Получатель получает событие `message` |
| Отправка при отключённом получателе | Сообщение остаётся в БД |
| Повторный вход | История загружается |
| Создать group-чат | Группа создана, создатель добавлен участником |
| Добавить участника в группу | Новый участник видит группу и сообщения |
| Отправить сообщение в группу | Сообщение получают участники |
| Добавить участника не администратором | Сервер возвращает `forbidden` |
| Отключение клиента | Сервер не завершается |
| Два клиента одновременно | Сообщения не смешиваются |

## 15. Критерии готовности сервера

| Критерий | Готово, если |
|---|---|
| TCP | Сервер принимает несколько соединений |
| Протокол | Все команды передаются как валидный JSON |
| Безопасность | Пароли хранятся только в виде хеша |
| Авторизация | Команды защищены token-сессией |
| БД | Сообщения сохраняются до их доставки |
| Доступ | Пользователь видит только свои чаты |
| Надёжность | Отключение клиента не останавливает сервер |
| Клиенты | `Client1` и `Client2` могут выполнить полный сценарий |
